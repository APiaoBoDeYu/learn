1. 有没有直接从torch转cuda的工具：
有，但要先区分你说的“从 torch 转 CUDA”是哪一种。
如果你的意思是让 PyTorch 模型跑在 GPU 上，这本来就是 PyTorch 的基本能力，把模型和张量放到 CUDA 设备上就行，不需要“转成 CUDA 代码”。如果你的意思是把 PyTorch 计算编译成更优化的 GPU 执行形式，主流直接工具是 torch.compile；PyTorch 官方教程把它描述为“以很少代码改动，通过 JIT 编译让 PyTorch 代码更快”，会把 PyTorch 代码编译成优化后的 kernel。(docs.pytorch.org)
如果你想要的是把模型专门编译到 NVIDIA TensorRT，比较直接的是 Torch-TensorRT。官方文档说明它就是“为 NVIDIA GPU 编译 PyTorch 模型”的工具，支持通过 torch.compile 做 JIT，也支持通过 torch.export 做 AOT 导出。(docs.pytorch.org)
如果你想要的是把某段 PyTorch 算子/逻辑手写成接近 CUDA kernel 的形式，常用的是 Triton。Triton 官方把自己定义成一个“并行编程语言和编译器”，目标是让你用 Python 写高性能 GPU kernel；它不是把任意 Torch 代码一键翻译成 .cu，而是适合重写热点 kernel。(triton-lang.org)
所以结论是：
- 没有一个通用的一键工具，能把任意 torch 程序完整“翻译成你可读的 CUDA C++ 源码”。
- 想直接加速现有 PyTorch 模型：先看 torch.compile。(docs.pytorch.org)
- 想部署到 NVIDIA 推理栈：看 Torch-TensorRT。(docs.pytorch.org)
- 想自己写/改 GPU kernel：看 Triton 或 PyTorch CUDA Extension；Triton 更像“写 kernel 的工具”，不是通用自动翻译器。(triton-lang.org)

2. 我说的是Torch-TensorRT
对，如果你说的是 Torch-TensorRT，那它可以算是“把 PyTorch 模型编译到 NVIDIA GPU 上跑”的直接工具。不过更准确地说，它不是把模型变成你手写可见的 .cu/CUDA C++ 源码，而是把 PyTorch 模型中的可支持部分编译成 TensorRT engine 来执行。PyTorch 官方文档也直接把 Torch-TensorRT定位成用于“为 NVIDIA GPU 编译 PyTorch 模型”的编译器。(docs.pytorch.org)
你可以把它理解成：
- 输入：PyTorch model
- 输出：更适合 NVIDIA GPU 执行的 TensorRT 表示/engine
- 目的：推理加速
  而不是“导出成 CUDA 源码给你继续手改”。它支持几条常见路径，包括通过 torch.compile 集成，以及基于 torch.export 的导出式工作流。(docs.pytorch.org)
所以如果你的原问题是“有没有直接从 torch 转 CUDA 的工具”，站在工程实践上：
- 做推理加速：Torch-TensorRT 是很直接的路线。(docs.pytorch.org)
- 想拿到 CUDA 源码：Torch-TensorRT 不是干这个的。它主要是把模型编译进 TensorRT 执行栈。(docs.pytorch.org)
一个很典型的用法大概是这样：
import torch
import torch_tensorrt

model = MyModel().eval().cuda()
inputs = [torch.randn(1, 3, 224, 224).cuda()]

trt_model = torch_tensorrt.compile(
    model,
    ir="dynamo",
    inputs=inputs,
    enabled_precisions={torch.float16},
)
这类接口就是“把 PyTorch 模型编译成 TensorRT 可执行形式”的意思，不是生成 .cu 文件。这个方向和官方 torch.compile 集成也是打通的。(docs.pytorch.org)

3. 你列举的torch_tensorrt.compile是torch2engine吗还有没有别的工
不完全是。
torch_tensorrt.compile(...) 的官方语义是“把 PyTorch 模型编译后返回一个可直接运行的 PyTorch Module / ScriptModule / GraphModule / callable”，也就是编译后仍以 PyTorch 可调用对象的形式使用，不是直接给你一个裸的 TensorRT engine 字节串。(docs.pytorch.org)
如果你说的 torch2engine 是“直接导出 TensorRT engine”这个意思，那么在当前 Torch-TensorRT 官方 Python API 里，更对应的是 torch_tensorrt.convert_method_to_trt_engine(...)。这个接口会把模块方法转换成serialized TensorRT engine，返回 bytes。(docs.pytorch.org)
所以可以这样对应理解：
- torch_tensorrt.compile(...)
  返回“编译后的可执行 PyTorch 模块”。(docs.pytorch.org)
- torch_tensorrt.convert_method_to_trt_engine(...)
  返回“序列化后的 TensorRT engine”。(docs.pytorch.org)
除了这两个，Torch-TensorRT 现在官方主路线还有几种：
- torch.compile(model, backend="torch_tensorrt", ...)
  这是官方推荐的 JIT 风格入口之一，用 Torch-TensorRT 作为 torch.compile 后端。(docs.pytorch.org)
- torch_tensorrt.dynamo.compile(exported_program, ...)
  这是 Dynamo / torch.export 路线里的主 API，输入通常是 ExportedProgram，输出是 GraphModule。(docs.pytorch.org)
- torch_tensorrt.ts.compile(...)
  这是 TorchScript 路线，输入 ScriptModule，输出优化后的 TorchScript module。官方文档里这一套还在，但 ts、fx、ptq 模块现在已被标成 maintenance mode，新项目更推荐 Dynamo 前端，也就是 torch.compile 或 torch.export 路线。(docs.pytorch.org)
- torchtrtc
  这是官方 CLI，可以编译 TorchScript 模块，并且能输出嵌入 engine 的 TorchScript 程序，或者直接输出 TensorRT PLAN 文件。(docs.pytorch.org)
如果你是从“我要一个 engine 文件”这个目标出发，通常优先看：
- Python 里：convert_method_to_trt_engine(...)。(docs.pytorch.org)
- 命令行里：torchtrtc，它能直接产出 PLAN。(docs.pytorch.org)

最实用的选择可以直接这么看：
- 想少改代码加速推理：用 torch.compile(..., backend="torch_tensorrt")。
- 想在 Python 里编译后继续像 PyTorch 模块那样调用：用 torch_tensorrt.compile(...)。
- 想直接拿 TensorRT engine：用 torch_tensorrt.convert_method_to_trt_engine(...)。
- 想导出成文件、走命令行流程：用 torchtrtc。
- 老 TorchScript 项目兼容：才考虑 torch_tensorrt.ts.compile(...)。
一句话总结：
如果你说的 torch2engine 是“直接出 TensorRT engine”，那最像的是 convert_method_to_trt_engine(...)，不是 torch_tensorrt.compile(...)。

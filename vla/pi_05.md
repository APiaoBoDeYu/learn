# π0.5 论文精读：具备开放世界泛化能力的 VLA 模型

> 论文：*π0.5: a Vision-Language-Action Model with Open-World Generalization*
> 作者：Physical Intelligence（Kevin Black, Danny Driess, Chelsea Finn, Sergey Levine, Karl Pertsch 等）
> 链接：https://www.pi.website/download/pi05.pdf ，博客：https://pi.website/blog/pi05

---

## 0. 一句话总结

**π0.5 = π0 的架构 + 一套"异构数据协同训练（co-training）"配方 + "先想子任务、再出动作"的分层推理。**
只用约 400 小时移动机械臂数据（加上大量其他机器人数据、网络数据、子任务标注、人类口头指令），就让机器人在**训练中从未见过的真实家庭**里完成 10~15 分钟的长程任务（收拾厨房、整理卧室、铺床等）。

论文的核心论点：**泛化不是靠单一数据源"堆量"实现的，而是靠从多种来源迁移知识。** 在第一阶段训练的样本中，97.6% 都不是"移动机械臂在家里干活"的数据。

---

## 1. 背景与动机

### 1.1 问题：VLA 在"野外"泛化能力如何？

已有 VLA（RT-2、OpenVLA、π0 等）大多在与训练数据非常接近的环境中评测。想让机器人进入一个**完全陌生的厨房**去收拾，需要多个层次的泛化：

| 泛化层次 | 例子 | 靠什么解决 |
|---|---|---|
| 低层技能泛化 | 抓起一把没见过的刀、盘子 | 足够多样的场景/物体的机器人动作数据 |
| 技能重组 | 把已有技能用新的方式/顺序组合 | 高层任务结构的学习 |
| 语义理解 | 该开哪个抽屉？台面上哪个东西最可能是沥水架？ | 先验知识（网络数据、VLM 预训练） |

靠"暴力扩大机器人数据采集"去覆盖所有家庭场景是不现实的。

### 1.2 思路：像人一样，从多种来源迁移经验

人的经验也不全是亲身实践：有读书看来的、别人告诉的、其他任务里迁移的。类比到机器人：
- 有直接相关的一手经验（目标机器人、目标任务）；
- 有来自其他机器人本体、其他环境的经验；
- 有完全不同模态的数据：口头指令、网络图文任务、高层语义预测……

**VLA 的好处在于**：它把所有模态都转成 token 序列，用同一个序列模型处理，所以天然可以把这些异构数据混在一起训练。

## 2. 预备知识（Preliminaries）

标准 VLA 的模仿学习目标：

$$\max_\theta \ \mathbb{E}_{(a_{t:t+H}, o_t, \ell)\sim\mathcal{D}} \log \pi_\theta(a_{t:t+H} \mid o_t, \ell)$$

- $o_t$：观测，包括多路相机图像 $I^1_t,\dots,I^n_t$ 和本体状态 $q_t$（关节角等）
- $\ell$：语言指令
- $a_{t:t+H}$：动作块（action chunk），一次预测未来 H 步动作

动作的两种表示方式：
1. **离散 token**（如 FAST tokenizer：对动作块做 DCT 变换 + BPE 压缩）→ 训练快、与 VLM 训练方式一致，但推理要自回归逐 token 解码，**慢**。
2. **连续表示 + 扩散/flow matching**（π0 的做法）→ 表达力强、推理可并行去噪，**快**，适合实时控制。π0 中处理动作 token 的是一组单独的、更小的权重，称为 **action expert**（类似 MoE 的思想）。

π0.5 的关键设计之一就是把这两者结合起来（见 3.3）。

## 3. π0.5 模型

### 3.1 分布分解：高层 + 低层，同一个模型

模型建模的联合分布：

$$\pi_\theta(a_{t:t+H}, \hat\ell \mid o_t, \ell) = \underbrace{\pi_\theta(a_{t:t+H} \mid o_t, \hat\ell)}_{\text{低层推理}} \cdot \underbrace{\pi_\theta(\hat\ell \mid o_t, \ell)}_{\text{高层推理}}$$

- $\ell$：总任务指令，如 "put away the dishes"
- $\hat\ell$：模型输出的文本，可以是**子任务**（如 "pick up the plate"），也可以是网络 VQA 数据的答案
- 注意：**动作只依赖子任务 $\hat\ell$，不直接依赖总任务 $\ell$**

和以往"VLM 做规划 + 单独的低层策略执行"的两模型方案（SayCan、Hi Robot 等）不同，π0.5 **高低层是同一个模型**，更像是 chain-of-thought：先"想"出下一步做什么，再基于这个想法输出动作。但与 embodied CoT 不同的是，高层推理的频率低于低层动作推理。

### 3.2 架构

整体是一个 transformer：

$$y_{1:N} = f\big(x_{1:N},\ A(x_{1:N}),\ \rho(x_{1:N})\big)$$

- $x_i$ 可以是：文本 token、图像 patch、或 flow matching 中的带噪动作（连续值）
- $\rho(x_i)$：token 类型 → 决定用哪个编码器、用 transformer 里哪套专家权重
  - 图像 → 视觉编码器（SigLIP，来自 PaliGemma）
  - 文本 → embedding 矩阵
  - 连续动作 → 线性投影 + **action expert** 权重
- $A(x_{1:N})$：注意力掩码矩阵
- 输出分两部分：前 M 个是文本 logits（用于采样 $\hat\ell$ 或 FAST 动作 token），后 H 个由 action expert 输出、线性映射为连续动作的速度场
- **本体状态 $q_t$ 被离散化后作为文本 token 输入**（π0 中是连续投影输入，这是一处区别）

具体规格（附录 E）：

| 组件 | 配置 |
|---|---|
| VLM 主干（PaliGemma 2B 初始化） | width=2048, depth=18, mlp_dim=16384, heads=18, kv_heads=1 (MQA), head_dim=256 |
| Action expert（~300M，随机初始化） | width=1024, mlp_dim=4096，其余同上 |
| 动作块长度 | 50 步（H=49 下标），50Hz 控制 → 约 1 秒 |
| 时间步注入 | **与 π0 不同**：τ 经过正弦编码 + MLP（swish(W2·swish(W1·φ(τ)))），再通过 **adaptive RMSNorm** 注入 action expert 每一层；π0 是把 τ 与带噪动作拼接后融合 |

### 3.3 离散 + 连续：两种动作表示同时训练

动机：
- FAST 离散 token 训练快、稳定，语言跟随好；
- 但离散 token 推理需要自回归解码，实时控制太慢；
- 理想方案：**用离散动作训练，用 flow matching 推理**。

于是联合损失为（式 1）：

$$\mathbb{E}\Big[\ \underbrace{H\big(x_{1:M}, f^\ell_\theta(o_t,\ell)\big)}_{\text{文本 + FAST 动作 token 的交叉熵}} \;+\; \alpha\ \underbrace{\big\|\omega - a_{t:t+H} - f^a_\theta(a^{\tau,\omega}_{t:t+H}, o_t, \ell)\big\|^2}_{\text{flow matching 损失}}\ \Big]$$

其中 $a^{\tau,\omega} = \tau a + (1-\tau)\omega,\ \omega\sim\mathcal{N}(0,I)$，网络预测速度场 $\omega - a$。

- **预训练阶段 α = 0**：纯 VLM 式的 next-token prediction，动作也用 FAST token；
- **后训练阶段 α = 10**：加入 action expert，同时训练两种表示；
- **推理时**：先自回归解码文本（子任务）$\hat\ell$，然后 action expert 做 **10 步去噪**得到连续动作块。

> 小注：flow matching 的时间方向约定在论文与代码中可能写法不同（openpi 实现中常写成 t=1 为噪声、从 1 积分到 0），本质等价，看代码时注意一下符号即可。

时间步采样沿用 π0：不用均匀分布，而是 $p(\tau)=\text{Beta}(\frac{s-\tau}{s};\ \alpha=1.5, \beta=1)$，s=0.999，侧重于噪声更大的时间步（论文所说的 "low time-steps"）。

### 3.4 注意力掩码（附录 E，Fig. 18）

```
                 被关注的 key →
               [图像|指令|状态]  [FAST动作token]  [action expert token]
query ↓
图像/指令/状态      双向(prefix)        ✗                 ✗
FAST 动作 token    ✓               因果(自回归)          ✗
action expert      ✓                  ✗              双向(彼此可见)
```

要点：
1. 前缀（图像、prompt、本体状态）之间是**双向注意力**；
2. FAST token 关注前缀 + 自回归关注之前的 FAST token；
3. action expert 的 token 关注前缀和彼此，但**看不到 FAST token** —— 防止"答案泄漏"（两种表示描述的是同一段动作，如果能看到就可以直接抄）；
4. 信息**单向**从 VLM 流向 action expert，VLM 不关注 action expert —— 这样加入 action expert 不会干扰 VLM 本身的表示。

## 4. 训练配方（本文最核心的部分）

### 4.1 两阶段总览（Fig. 3）

```
PaliGemma（网络数据预训练的 VLM）
        │
        ▼  预训练：280k 步，全部离散 token（α=0）
        │  数据：MM + ME + CE + HL + WD
        ▼
初始 VLA（离散 FAST 动作）
        │
        ▼  后训练：80k 步，加入 action expert（α=10）
        │  数据：MM + ME（过滤后）+ WD + HL(多环境部分) + VI
        ▼
π0.5（高层子任务预测 + flow matching 低层动作）
```

### 4.2 预训练数据（5 类）

| 缩写 | 名称 | 内容 | 作用 |
|---|---|---|---|
| **MM** | Diverse Mobile Manipulator | ~400 小时，移动机械臂在 ~100 个真实家庭里做家务 | 与评测最直接相关 |
| **ME** | Multi-Environment non-mobile | 固定底座的单/双臂机器人在多种家庭环境中采集 | 轻便易搬运 → 覆盖更多家庭；本体不同 |
| **CE** | Cross-Embodiment lab data | 实验室中多种机器人做多种任务（收拾桌子、叠衣服、磨咖啡豆…），含开源 OXE 数据集 | 任务多样性、跨本体迁移 |
| **HL** | High-Level subtask prediction | 对 MM/ME/CE 中的多步任务**人工标注子任务**文本，以及相关物体的**边界框** | 学会把"打扫卧室"拆成"整理毯子""拿起枕头"；先预测 bbox 再预测子任务 |
| **WD** | Multi-modal Web Data | 图像描述（CapsFusion、COCO）、VQA（Cambrian-7M、PixMo、VQAv2）、物体定位（含额外的室内家居 bbox 数据） | 保持/增强语义与视觉知识 |

动作数据的工程细节：
- 同时有**关节空间**和**末端执行器空间**两种控制目标，用 prompt 里的 `<control mode> joint/end effector <control mode>` 区分；
- 每个数据集的每个动作维度，用 1% 和 99% 分位数归一化到 [-1, 1]；
- 动作维度统一为所有数据集中最大的维度，低维机器人**补零**。

### 4.3 后训练数据

目的：①专精于"家庭移动操作"；②加入 action expert，实现快速连续动作生成。

- **MM + ME 的机器人数据**，只保留**成功的、且长度低于阈值**的 episode；
- **WD**：保持语义与视觉能力；
- **HL**：仅保留多环境数据集对应的那部分；
- **去掉 CE**（实验室数据），聚焦移动操作和多样环境；
- 新增 **VI（Verbal Instructions，口头指令示教）**：专家用户用**语言实时"遥操作"机器人** —— 一步步给出子任务指令（如"拿起杯子"），由已训练好的低层策略执行。这相当于为高层策略提供"好的子任务输出"的示范。

> VI 是一种很有意思的新监督形式：不是示范**动作**，而是示范**决策**。数据量很小（约占高层移动操作样本的 11%），但实验显示对高层推理至关重要。

### 4.4 每个训练样本可能长什么样（Fig. 4 的直觉）

```
[多路图像] [任务: "clean the bedroom"] [状态token]
   → 文本输出: "<bbox: pillow ...>  pick up the pillow"     (HL)
   → FAST 动作 token ...                                      (预训练)
   → action expert 连续动作块                                 (后训练)

[网页图片] [问题: "What is on the table?"]
   → 文本输出: "A cup and a plate."                           (WD)
```

## 5. 推理流程

```python
# 伪代码：π0.5 在线控制
while not done:
    obs = get_obs()                     # 4 路相机 + 本体状态
    # 高层推理（频率较低）：用 4 路相机（前/后/左右腕）
    subtask = model.generate_text(obs, task_prompt)    # e.g. "pick up the cup"
    # 低层推理：用 2 个腕部相机 + 前向相机
    a = sample_noise(shape=(50, d))
    for k in range(10):                 # 10 步 flow matching 积分
        v = model.action_expert(a, tau_k, obs, subtask)
        a = a + delta * v
    execute(a)                          # 50Hz 下执行动作块，PD 控制器跟踪
```

整个系统是**完全端到端**的：没有单独的导航模块、轨迹规划或碰撞检测，模型直接输出两条手臂、夹爪、升降躯干的目标位姿和底盘目标速度。

## 6. 机器人平台（Fig. 5）

- 两种移动机械臂平台，各有：
  - 两条 6 自由度机械臂 + 平行夹爪，腕部单目 RGB 相机；
  - 全向轮式底盘（状态/动作 = 2D 线速度 + 1D 角速度）；
  - 躯干升降机构（1D 上下，或 2D 上下+前后）；
  - 双臂之间安装前向、后向相机。
- 总状态/动作维度：**18 或 19**。
- 控制：50Hz，动作分块，简单 PD 控制器跟踪。

## 7. 实验

**所有实验都在训练中没见过的环境中进行。** 定量对比用若干"模拟家庭"（mock homes，可控、可复现），最终评估在 **3 个真实家庭**中进行。

评测任务（附录 B）及打分规则（结果为得分百分比）：

| 任务 | 打分 |
|---|---|
| Dishes in Sink | 4 件餐具，每拿起一件 +1，每放进水槽一件 +1 |
| Items in Drawer | 放进抽屉 +1，关好抽屉 +1 |
| Laundry Basket | 走过去捡起衣服 +1，放进/放在洗衣篮上 +1，完全放进去 +1 |
| Make Bed | 拉平毯子 +1，两个枕头各 +1，毯子非常平整 +1，枕头非常整齐 +1 |

每个策略每个任务通常跑 10 次，统计显著性用双侧 t 检验。

围绕 5 个问题：

### Q1：能否在真实的新家庭中泛化？（Fig. 7）
可以。在 3 个新家庭的厨房和卧室中，π0.5 能稳定完成多阶段任务（每个约 2~5 分钟），只需给一个简单的高层指令（如"把碗碟放进水槽"），模型自己推断子步骤（"拿起杯子"）。而且**mock 环境中的表现能代表真实家庭中的表现**，说明 mock 评测是可信的。

### Q2：泛化如何随训练环境数量变化？（Fig. 8, 9）
- 设置：移动操作数据分别来自 3、12、22、53、82、104 个地点；为节省算力，预训练用不含 MM 的机器人数据，然后用不同数量地点的 MM 数据做后训练（40k 步，控制看到的样本数相同，从而排除数据量的影响）。
- 结论：
  - 任务表现随地点数增加而提升；
  - **104 个地点的模型 ≈ 直接在测试家庭数据上训练的对照模型** —— 也就是说，见过足够多的环境后，"没见过测试环境"几乎不再是劣势；
  - 不用协同训练配方（直接在 MM 上训练）的基线明显更差 —— **即使见过测试家庭的数据，没有其他数据源也不行**；
  - 语言跟随率和成功率也随地点数提升，分布内物体提升得更快，分布外（OOD）物体也在提升。

### Q3：协同训练配方中每部分有多重要？（Fig. 10, 11, 16）
消融：no WD / no ME / no CE / no ME&CE。
- **去掉 ME 或 CE 都显著变差，都去掉更差** → 跨本体迁移（不同环境 ME、不同任务 CE）收益巨大；
- **去掉 WD 对端到端任务得分影响不显著**，但对**OOD 物体的语言跟随**影响很大 —— 网络数据提供了对各种物体的广泛知识；
- 分任务看：Items in Drawer（需要认识大量常见物体）对 WD 和跨本体数据都敏感；Dishes in Sink 主要依赖机器人数据中学来的操作策略，对 WD 不敏感。

### Q4：和其他 VLA 比如何？（Fig. 12, 15）
对比 π0 和 **π0-FAST+Flow**（使用式 1 的混合训练，但只用带动作的数据，没有 HL/WD，因此不能做高层推理）。
- π0.5 显著优于两者；
- 即使把 π0 训练到 300k 步也追不上 → 印证了 FAST 论文的结论：**离散 token 训练比纯扩散训练算力效率高**；
- 语言跟随：π0.5 略好于 π0-FAST+Flow，远好于 π0 → 离散 token 训练对语言跟随很重要。

### Q5：高层推理有多重要？（Fig. 13, 17）
低层统一用 π0.5，对比不同高层策略：

| 变体 | 说明 | 结果 |
|---|---|---|
| **π0.5（完整）** | 同一模型做高层+低层 | **最好**，甚至超过 human HL |
| implicit HL | 运行时不做高层推理，但训练数据含 HL | **第二好** |
| no VI | 去掉口头指令数据 | 显著变差 |
| no WD | 去掉网络数据 | 显著变差 |
| no HL | 训练和推理都不含高层 | 显著变差 |
| GPT-4 HL | 零样本提示 GPT-4 做高层（给定常用子任务标签列表） | **最差** |
| human HL | 人类专家当"神谕"高层 | 被完整 π0.5 超过 |

几个值得注意的结论：
1. **implicit HL 排第二**：即使推理时不显式预测子任务，**只要训练时包含子任务预测数据**，就能获得大部分收益 —— 协同训练本身就让模型隐式学到了任务结构；
2. **VI 数据虽小但关键**；
3. **WD 对高层推理收益很大**；
4. **零样本大模型（GPT-4）不行**，必须用机器人数据去适配 VLM；
5. 模型自己的高层甚至比人类好 —— 可能因为它学到了"低层策略擅长执行什么样的子任务"。

## 8. 局限与未来方向

- **仍会犯错**：不熟悉的抽屉把手、物理上难打开的柜子；部分可观测问题（手臂挡住了要擦的污渍）；高层推理容易"分心"（放东西时反复开关抽屉）。
- **指令较简单**：能理解的 prompt 复杂度受限于训练标注，可通过更丰富的人工/合成标注改进。
- **上下文较短、无记忆**：难以处理跨房间导航、记住物品存放位置等任务。
- **数据源还可以更广**：例如口头指令这种新的监督形式值得深入探索。

## 9. 我的理解：π0.5 的关键 takeaways

1. **数据配方 > 模型结构创新。** 架构基本沿用 π0，真正的贡献是"什么数据、怎么混、分几阶段"。MM 只占预训练样本的 2.4%，但其他数据带来的迁移才是泛化的来源。

2. **"离散训练、连续推理"是很实用的工程折中。**
   - 预训练用 FAST token：和 VLM 训练范式一致，快且稳定，保留语言能力；
   - 后训练加 action expert：推理时 10 步去噪，满足 50Hz 实时控制；
   - 注意力掩码保证两种表示互不泄漏、且 action expert 不干扰 VLM。

3. **分层推理在单一模型中完成，本质是一种 "具身 CoT"。** 子任务文本是一个可解释、可监督、可由人干预（VI）的中间变量；而且高层可以直接受益于网络数据和 VLM 知识，低层则受益于跨本体动作数据 —— **不同层级从不同数据源获取知识**。

4. **跨本体数据非常重要。** 固定机械臂（ME）、实验室多机器人（CE）的数据对移动机械臂帮助很大，说明低层操作技能可以跨本体迁移。

5. **环境多样性的规模效应。** ~100 个家庭就能让模型在新家庭里的表现接近"在测试家庭训练"的水平。

## 10. 术语速查

- **VLA**：Vision-Language-Action 模型，在 VLM 基础上输出机器人动作
- **Action chunk**：一次预测多步动作（这里 50 步 ≈ 1 秒）
- **FAST**：基于 DCT + BPE 的动作 tokenizer，把连续动作块压缩成少量离散 token
- **Flow matching**：学习从噪声到数据的速度场，推理时数值积分（这里 10 步）生成样本
- **Action expert**：处理连续动作 token 的独立的小 transformer 权重（~300M），与 VLM 通过注意力交互
- **Co-training**：多种任务/数据源混合在一起联合训练
- **MM / ME / CE / HL / WD / VI**：移动操作数据 / 多环境非移动机器人数据 / 实验室跨本体数据 / 高层子任务预测 / 网络多模态数据 / 口头指令示教
- **adaRMSNorm**：用条件信息（这里是 τ）生成 RMSNorm 的缩放/偏移参数，类似 DiT 中的 adaLN
- **OOD**：Out-of-distribution，训练中未出现过的类别

# 07 构建期检查

> 另见：[brain-service 篇第 1 章 1.11](../brain-service-docker-deploy/01_dockerfile_instructions.md)

思路是：问题能在构建时发现，就不要等到镜像部署到机器人上才发现。`RUN` 的命令返回非 0 退出码，构建就会失败，所以只要写出"有问题时返回非 0"的命令即可。

## set -eux

原文件的多行 `RUN` 都以它开头：

```dockerfile
RUN set -eux; \
    mkdir -p /export/brain; \
    cp -a src /export/brain/
```

| 选项 | 作用 |
|---|---|
| `-e` | 任何一条命令失败，立即退出 |
| `-u` | 使用未定义的变量时报错，防止 `rm -rf $DIR/` 在 `DIR` 为空时变成 `rm -rf /` |
| `-x` | 执行前打印每条命令，构建日志里能看到具体执行到哪一步 |

没有 `-e` 时，`a; b; c` 中 `a` 失败了 `b` 和 `c` 照样执行，最终退出码只看 `c`，错误就被吞掉了。有了 `-e`，用 `;` 分隔和用 `&&` 串联的效果一样。

## 用 test 做断言

```dockerfile
RUN test -f /export/brain/scripts/serve_policy_rtc.py; \
    test -d /export/brain/packages/openpi-client/src/openpi_client
```

- `test -f 路径`：是普通文件则返回 0，否则返回 1。
- `test -d 路径`：是目录则返回 0。
- `test -z "字符串"`：字符串为空则返回 0。

brain-service 的 Dockerfile 里有一个用法：`test -z "$(find /root/brain-service -name '*.py' -print -quit)"`，意思是"找不到任何 .py 文件"。

## 语法检查：compileall

```dockerfile
RUN python3 -m compileall -q /export/brain /export/body
```

- 把目录下所有 `.py` 编译成字节码，`-q` 只输出错误。
- 有文件存在语法错误时返回非 0，构建失败。
- 它**只检查语法**，不执行代码，所以发现不了 import 失败、缺依赖之类的问题。

原文件编译完马上删掉生成的 `__pycache__`，只要检查结果，不把 `.pyc` 带进镜像。

## 导入冒烟测试

```dockerfile
RUN python3 -B -c "import openpi, openpi_client; \
from openpi.training import config; \
assert openpi.__file__.startswith('/workspace/src/'), openpi.__file__; \
print('brain imports OK', openpi.__file__)"
```

- 真正 import 关键模块，能发现缺依赖、路径配错等问题。不需要 GPU 和模型权重。
- `assert openpi.__file__.startswith('/workspace/src/')` 确认加载的是刚拷进来的代码，不是 site-packages 里的同名包。
- `-B`：不写 `__pycache__`。
- `-c`：执行后面的字符串。

**引号和换行**：

- 行尾的 `\` 先被 Dockerfile 拼成一行，所以 Python 代码最后是一行，只能用 `;` 分隔语句，不能写 `if`、`for` 这类需要缩进的代码块。
- 外层双引号把整段代码作为一个参数交给 `-c`，Python 里的字符串于是改用单引号。

## find 的常用写法

```dockerfile
find /export -name '*_test.py' -delete
find /export -type d -name '__pycache__' -prune -exec rm -rf {} +
```

- `-name 'pattern'`：按文件名匹配。模式要加引号，防止 shell 先展开 `*`。
- `-delete`：删除匹配的文件。
- `-type d`：只匹配目录。
- `-prune`：匹配到后不再进入该目录，否则 find 会试图遍历刚被删掉的目录并报错。
- `-exec rm -rf {} +`：`{}` 代表匹配到的路径，`+` 表示把所有结果一次性交给 `rm`。写成 `\;` 则每个结果执行一次 `rm`。

## 动手试一试

```bash
mkdir -p ~/docker-lab/ch07/app && cd ~/docker-lab/ch07
echo 'print("ok")'  > app/good.py
echo 'print("bad"'  > app/bad.py          # 少一个右括号

cat > Dockerfile <<'EOF'
FROM python:3.12-slim
COPY app /app
RUN set -eux; \
    python3 -m compileall -q /app; \
    test -f /app/good.py
EOF

docker build --progress=plain -t lab:ch07 .     # 构建失败，日志指出 bad.py 的语法错误
```

修好 `bad.py` 后再构建会成功。再试试把 `test -f /app/good.py` 改成一个不存在的文件，观察构建失败。

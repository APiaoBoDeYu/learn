# 01 基础概念

> 另见：[brain-service 篇第 0 章：心智模型](../brain-service-docker-deploy/00_overview.md)

## 镜像和容器

- **镜像（image）**：一个只读的文件系统快照，加上一份配置（环境变量、工作目录、启动命令等）。可以理解为程序的安装包。
- **容器（container）**：用镜像启动的进程。启动时 Docker 在镜像上面加一个可写层，容器里的改动都写在这一层，删掉容器改动就没了。

一个镜像可以启动任意多个容器，它们互不影响。

## 层（layer）

镜像由多层叠加而成。Dockerfile 里的 `RUN`、`COPY` 每执行一条就产生一层，记录这一步对文件系统的增删改。

```
┌──────────────────────┐  ← 容器运行时的可写层
├──────────────────────┤  COPY 代码          （第 3 层）
├──────────────────────┤  RUN pip install    （第 2 层）
├──────────────────────┤  FROM python:3.12   （基础镜像的若干层）
└──────────────────────┘
```

层有一个很重要的特点：**上层删不掉下层的数据**。如果第 2 层写入了 1 GB 文件，第 3 层执行 `rm` 只会加一个"已删除"标记，容器里看不到这个文件，但镜像体积不变，导出镜像还能把文件恢复出来。第 06 章的多阶段构建就是为了解决这个问题。

## 构建上下文（build context）

执行构建时：

```bash
docker build -f path/to/Dockerfile -t myimage:1.0 <上下文目录>
```

- `-f`：Dockerfile 的路径，不写时默认是 `<上下文目录>/Dockerfile`。
- `-t`：镜像名和标签，格式 `仓库/名字:标签`。
- 最后的参数是**构建上下文**。Docker 把这个目录发给构建引擎，Dockerfile 里的 `COPY` 只能拷贝这个目录里的文件。

原文件的上下文是整个仓库根目录，所以 `COPY brain/vla/openpi ...` 这样的相对路径才能成立。

## 动手试一试

```bash
mkdir -p ~/docker-lab/ch01 && cd ~/docker-lab/ch01
cat > Dockerfile <<'EOF'
FROM python:3.12-slim
RUN echo "hello" > /hello.txt
EOF
docker build -t lab:ch01 .
docker run --rm lab:ch01 cat /hello.txt     # 输出 hello
docker history lab:ch01                      # 查看每一层及其大小
```

`--rm` 表示容器退出后自动删除。`docker history` 能看到 `RUN echo` 那一层，大小只有几个字节。

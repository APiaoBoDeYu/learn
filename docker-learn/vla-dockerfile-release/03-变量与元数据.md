# 03 变量与元数据：ARG、ENV、LABEL

> 另见：[brain-service 篇第 1 章 1.5–1.6（含 ARG 作用域实测）](../brain-service-docker-deploy/01_dockerfile_instructions.md)、[lab05](../brain-service-docker-deploy/code/lab05_arg_scope/)

## ARG：构建参数

```dockerfile
ARG ENV_TAG                       # 无默认值
ARG GIT_COMMIT=unknown            # 有默认值
```

构建时用 `--build-arg` 传值：

```bash
docker build --build-arg ENV_TAG=1.1.0 --build-arg GIT_COMMIT=$(git rev-parse HEAD) .
```

ARG **只在构建时存在**，容器运行时看不到它。

### ARG 的作用域

这是最容易出错的地方：

```dockerfile
ARG REGISTRY=robot-harbor.geekplus.com/gino     # ① 全局 ARG：写在第一个 FROM 之前
ARG ENV_TAG

FROM ${REGISTRY}/vla-brain-env:${ENV_TAG}       # ② FROM 行里可以用全局 ARG

RUN echo ${REGISTRY}                            # ③ 这里是空的！

ARG REGISTRY                                    # ④ 阶段内重新声明（不写值，继承全局默认值）
RUN echo ${REGISTRY}                            # ⑤ 现在有值了
```

规则总结：

- 第一个 `FROM` 之前的 ARG 是全局的，但只能用在 `FROM` 行。
- `FROM` 之后声明的 ARG 只属于当前阶段，下一个 `FROM` 开始就失效。
- 所以原文件在 `vla-brain` 和 `vla-body` 两个阶段里各写了一遍 `ARG GIT_COMMIT=unknown`。

## ENV：环境变量

```dockerfile
ENV PYTHONPATH=/workspace/src:/workspace \
    RELEASE_VERSION=2.1.0
```

- 一条 `ENV` 可以设多个变量，用 `\` 换行。
- 对后续的构建指令生效，**也写进镜像**，容器运行时一直存在。
- 运行时可以用 `docker run -e 名字=值` 覆盖。
- 老写法 `ENV 名字 值`（空格分隔）每条只能设一个，不推荐。

### 把 ARG 变成运行时变量

ARG 运行时看不到。想在容器里也能查到构建参数，就用 ENV 转一次：

```dockerfile
ARG GIT_COMMIT=unknown
ENV GIT_COMMIT=${GIT_COMMIT}
```

原文件就是这样做的：镜像里没有 `.git` 目录，进入运行中的容器执行 `echo $GIT_COMMIT` 就能知道代码是哪个提交。

## LABEL：镜像元数据

```dockerfile
LABEL org.opencontainers.image.revision="${GIT_COMMIT}" \
      org.opencontainers.image.version="${RELEASE_VERSION}"
```

- 键值对，写进镜像配置，不影响文件系统。
- `org.opencontainers.image.*` 是 OCI 规范定义的标准键名，各种镜像仓库和工具都认识。
- 不用启动容器就能查看：

```bash
docker inspect --format '{{json .Config.Labels}}' 镜像名
```

## ENV 和 LABEL 的区别

| | ENV | LABEL |
|---|---|---|
| 容器里的进程能读到 | 能 | 不能 |
| 不启动容器就能查 | 能（`docker inspect`） | 能 |
| 典型用途 | 程序配置、`PYTHONPATH` | 版本、来源、维护者 |

原文件两者都设，是为了在两种场景下都能追踪版本。

## 动手试一试

```bash
mkdir -p ~/docker-lab/ch03 && cd ~/docker-lab/ch03
cat > Dockerfile <<'EOF'
ARG BASE=python:3.12-slim
FROM ${BASE}

RUN echo "BASE in stage: [${BASE}]"

ARG GIT_COMMIT=unknown
LABEL org.opencontainers.image.revision="${GIT_COMMIT}"
ENV GIT_COMMIT=${GIT_COMMIT}
EOF

docker build --progress=plain --build-arg GIT_COMMIT=abc123 -t lab:ch03 .
docker run --rm lab:ch03 sh -c 'echo $GIT_COMMIT'                       # abc123
docker inspect --format '{{json .Config.Labels}}' lab:ch03               # 含 abc123
```

构建日志里 `BASE in stage: []` 是空的，验证了全局 ARG 在阶段内不可见。

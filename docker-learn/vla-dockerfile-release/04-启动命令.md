# 04 启动命令：ENTRYPOINT 和 CMD

这两条指令决定容器启动时执行什么。它们只写进镜像配置，构建时不执行。

## 两种写法

```dockerfile
CMD ["python", "main.py"]        # exec 形式（推荐）
CMD python main.py               # shell 形式，实际执行 /bin/sh -c "python main.py"
```

exec 形式的特点：

- 直接执行程序，不经过 shell，所以 `$VAR` 不会被展开。
- 程序就是容器里的 1 号进程，`docker stop` 发出的 SIGTERM 能直接送达，程序可以优雅退出。shell 形式的 1 号进程是 `sh`，信号可能传不到你的程序。
- 必须是合法 JSON，**只能用双引号**。写成 `['python']` 会被当作 shell 形式。

## 组合规则

容器实际执行的命令 = `ENTRYPOINT` + `CMD`。

```dockerfile
ENTRYPOINT ["/opt/nvidia/nvidia_entrypoint.sh"]
CMD ["python", "scripts/serve_policy_rtc.py", "--help"]
```

启动时执行：

```
/opt/nvidia/nvidia_entrypoint.sh python scripts/serve_policy_rtc.py --help
```

可以这样理解分工：

- `ENTRYPOINT`：固定的前置程序。`nvidia_entrypoint.sh` 是 NVIDIA NGC 镜像自带的脚本，打印版本信息、检查环境，最后执行 `exec "$@"`，也就是运行传给它的参数。
- `CMD`：默认参数，方便被替换。

## 覆盖方式

| 想覆盖 | docker run | docker-compose |
|---|---|---|
| CMD | 镜像名后直接跟命令：`docker run img python other.py` | `command:` |
| ENTRYPOINT | `docker run --entrypoint bash img` | `entrypoint:` |

**注意**：覆盖 ENTRYPOINT 会同时清掉镜像里的 CMD。在 docker-compose 里写了 `entrypoint:`，通常也要写 `command:`，否则启动时没有参数。

同一阶段里写多条 ENTRYPOINT 或 CMD，只有最后一条生效。

## 原文件为什么这样设

- `vla-brain` 的 CMD 是 `--help`：直接 `docker run` 只会打印用法然后退出，不会意外加载模型。真正的参数在 docker-compose 的 `command:` 里写。
- `vla-body` 的 CMD 是 `bash`：默认进入 shell，方便调试。实际运行命令同样交给 docker-compose。

## 动手试一试

```bash
mkdir -p ~/docker-lab/ch04 && cd ~/docker-lab/ch04
cat > entry.sh <<'EOF'
#!/bin/sh
echo "[entry] init done, running: $@"
exec "$@"
EOF
chmod +x entry.sh

cat > Dockerfile <<'EOF'
FROM python:3.12-slim
COPY entry.sh /entry.sh
ENTRYPOINT ["/entry.sh"]
CMD ["python", "-c", "print('default cmd')"]
EOF

docker build -t lab:ch04 .
docker run --rm lab:ch04                                   # 走默认 CMD
docker run --rm lab:ch04 python -c "print('override')"     # 只替换 CMD，entry.sh 仍执行
docker run --rm --entrypoint python lab:ch04 -c "print(1)" # 替换 ENTRYPOINT，entry.sh 不再执行
```

`exec "$@"` 里的 `exec` 让参数里的程序替换掉 shell，成为 1 号进程。去掉 `exec`，`sh` 会一直占着 1 号进程。

# 02 基础指令：FROM、RUN、COPY、WORKDIR

## FROM：选择基础镜像

```dockerfile
FROM python:3.12-slim
```

每个 Dockerfile（准确说是每个构建阶段）都以 `FROM` 开始。后续所有指令都在这个镜像的基础上执行。

原文件的基础镜像是自己团队构建的 env 镜像：

```dockerfile
FROM ${REGISTRY}/vla-brain-env:${ENV_TAG} AS builder
```

`${...}` 是变量，第 03 章讲；`AS builder` 是阶段名，第 06 章讲。

## RUN：在构建时执行命令

两种写法：

```dockerfile
RUN apt-get update && apt-get install -y curl      # shell 形式，等价于 /bin/sh -c "..."
RUN ["python3", "-c", "print('hi')"]               # exec 形式，不经过 shell
```

shell 形式支持 `&&`、管道、变量展开，日常用得最多。原文件的 `RUN` 都是 shell 形式。

**续行**：命令太长时，行尾写 `\`，Dockerfile 会先把多行拼成一行再交给 shell：

```dockerfile
RUN mkdir -p /export; \
    cp -a src /export/
```

**每个 RUN 都是独立的 shell**：在一个 `RUN` 里 `cd` 到某个目录，下一个 `RUN` 不会记得。要固定工作目录，用 `WORKDIR`。

## COPY：把文件拷进镜像

```dockerfile
COPY <源> <目标>
```

- 源路径相对于构建上下文，不能写 `../` 跳出上下文。
- 源是目录时，拷贝的是**目录里的内容**，不包括目录本身。
- 目标目录不存在会自动创建。
- 目标目录已存在时是**合并**：同名文件覆盖，其他文件保留。

```dockerfile
COPY brain/vla/openpi /src/brain
# 结果：brain/vla/openpi/src     → /src/brain/src
#       brain/vla/openpi/scripts → /src/brain/scripts
```

## WORKDIR：设置工作目录

```dockerfile
WORKDIR /workspace
```

- 之后的 `RUN`、`CMD`、`ENTRYPOINT` 都在这个目录执行。
- `COPY` 的目标写相对路径时，也相对于它。
- 目录不存在时自动创建。
- 容器启动后的默认目录也是它。

## 动手试一试

```bash
mkdir -p ~/docker-lab/ch02/app && cd ~/docker-lab/ch02
echo 'print("app running")' > app/main.py
echo 'print("test file")'   > app/main_test.py

cat > Dockerfile <<'EOF'
FROM python:3.12-slim
WORKDIR /workspace
COPY app /workspace/
RUN ls -la /workspace
RUN cd /tmp
RUN pwd
EOF

docker build --progress=plain -t lab:ch02 .
docker run --rm lab:ch02 python main.py
```

观察构建日志：

- `ls` 能看到 `main.py` 和 `main_test.py`，说明 `COPY app` 拷的是 `app` 目录里的内容。
- `RUN pwd` 输出 `/workspace`，不是 `/tmp`，说明 `cd` 不跨 `RUN`。

`--progress=plain` 让 BuildKit 打印完整日志，默认的折叠输出看不到 `ls` 的结果。

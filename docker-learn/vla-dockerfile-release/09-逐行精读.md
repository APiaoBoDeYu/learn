# 09 逐行精读 Dockerfile.release

原文件：`embodied_algo/docker-deploy/vla/Dockerfile.release`。每段后面标注了对应的章节，忘了可以回去翻。

## 第 1 行：解析器指令

```dockerfile
# syntax=docker/dockerfile:1
```

看起来是注释，其实是**解析器指令**，告诉 BuildKit 用 `docker/dockerfile:1`（1.x 最新版）这个前端镜像来解析文件。

- 必须写在文件第一行，前面不能有空行或其他注释，否则会被当成普通注释。
- 声明之后，即使本机 Docker 版本较旧，也能使用较新的 Dockerfile 语法。

第 2-23 行是普通注释，说明设计思路和哪些内容运行时挂载（checkpoints、缓存、日志、`/dev`）。

## 第 25-26 行：全局 ARG（第 03 章）

```dockerfile
ARG REGISTRY=robot-harbor.geekplus.com/gino
ARG ENV_TAG
```

- 写在第一个 `FROM` 之前，只能在 `FROM` 行使用。
- `ENV_TAG` 没有默认值，由 `build.sh` 用 `--build-arg ENV_TAG=...` 传入，默认取 `ENV_VERSION` 文件的内容。手动构建漏传时，镜像名会变成 `vla-brain-env:`，构建直接报错。

## 第 32 行：builder 阶段（第 06 章）

```dockerfile
FROM ${REGISTRY}/vla-brain-env:${ENV_TAG} AS builder
```

- 展开后类似 `robot-harbor.geekplus.com/gino/vla-brain-env:1.1.0`。
- 这个阶段只用来整理和检查代码，只需要一个 Python 3.12。两个 env 镜像的 Python 一样，用 brain 的即可。

## 第 34-35 行：拷入源码（第 02、05 章）

```dockerfile
COPY brain/vla/openpi /src/brain
COPY body/gino        /src/body
```

- 上下文是仓库根目录，由 `Dockerfile.release.dockerignore` 过滤：只放行这两个目录，并排除 checkpoints、data、日志、`.git`、`.env` 等。
- 拷贝的是目录里的内容：`brain/vla/openpi/src` 变成 `/src/brain/src`。

## 第 40-49 行：只保留运行时需要的文件（第 02、07 章）

```dockerfile
RUN set -eux; \
    mkdir -p /export/brain /export/body; \
    cd /src/brain; \
    cp -a src scripts packages LICENSE LICENSE_GEMMA.txt /export/brain/; \
    cd /src/body; \
    cp -a vla_body scripts configs /export/body/; \
    find /export -name '*_test.py' -delete; \
    find /export -name 'conftest.py' -delete; \
    find /export -type d -name '__pycache__' -prune -exec rm -rf {} +; \
    rm -f /export/body/scripts/test_gino.sh
```

- `set -eux`：出错即停、禁止未定义变量、打印每条命令。
- 用 `cp -a` 按白名单拷贝需要的目录。tests、docs、examples 不在名单里，自然进不来。`-a` 保留权限和符号链接。
- 再用 `find` 删掉散落在代码目录里的测试文件和缓存。
- 在 builder 里删文件没有代价，这些层不会进入最终镜像。
- 保留 LICENSE：openpi 是 Apache-2.0 协议，Gemma 模型有单独的使用条款，发布时需要附带。

## 第 53-60 行：构建期检查（第 07 章）

```dockerfile
RUN set -eux; \
    python3 -m compileall -q /export/brain /export/body; \
    find /export -type d -name '__pycache__' -prune -exec rm -rf {} +; \
    test -f /export/brain/scripts/serve_policy_rtc.py; \
    test -f /export/body/vla_body/__main__.py; \
    test -f /export/body/vla_body/lowlevel_robot.desc; \
    test -f /export/body/vla_body/startup_look_pose.json; \
    test -d /export/brain/packages/openpi-client/src/openpi_client
```

- `compileall` 检查所有代码的语法，检查完删掉生成的 `__pycache__`。
- `test` 断言关键文件存在：
  - brain 的入口 `serve_policy_rtc.py`
  - body 的入口 `vla_body/__main__.py`
  - body 运行需要的 `lowlevel_robot.desc` 和 `startup_look_pose.json`
  - 两边共用的 `openpi_client`
- 两个 body 数据文件不是 `.py`，如果被 `.dockerignore` 误排除，语法检查发现不了，所以单独检查。

## 第 65 行：vla-brain 阶段（第 06 章）

```dockerfile
FROM ${REGISTRY}/vla-brain-env:${ENV_TAG} AS vla-brain
```

从全新的 env 镜像开始，builder 阶段里的 `/src` 等文件都不会带进来。

## 第 67-73 行：版本信息和 PYTHONPATH（第 03 章）

```dockerfile
ARG GIT_COMMIT=unknown
ARG RELEASE_VERSION=unknown
LABEL org.opencontainers.image.revision="${GIT_COMMIT}" \
      org.opencontainers.image.version="${RELEASE_VERSION}"
ENV GIT_COMMIT=${GIT_COMMIT} \
    RELEASE_VERSION=${RELEASE_VERSION} \
    PYTHONPATH=/workspace/packages/openpi-client/src:/workspace/src:/workspace
```

- ARG 在 `FROM` 之后声明，只属于当前阶段。`build.sh` 传入实际的提交号和版本号。
- 版本信息同时写成 LABEL 和 ENV：
  - LABEL 用于不启动容器、直接 `docker inspect` 查镜像。
  - ENV 用于在运行中的容器里 `echo $GIT_COMMIT`。
- `PYTHONPATH` 的三个目录：
  - `/workspace/packages/openpi-client/src`：`import openpi_client`
  - `/workspace/src`：`import openpi`
  - `/workspace`：`scripts` 等顶层目录

## 第 78-80 行：放置代码（第 02、06 章）

```dockerfile
WORKDIR /workspace
COPY --from=builder /export/brain/ /workspace/
RUN mkdir -p /workspace/checkpoints
```

- env 镜像在 `/workspace` 留有 `pyproject.toml` 和 egg-info，用来登记依赖。`COPY` 是合并，这些文件会保留。
- `COPY --from=builder` 只拷整理好的 `/export/brain`。
- `checkpoints` 是空目录，作为运行时挂载模型权重的挂载点。启动命令里的 `checkpoints/...` 相对路径从 `/workspace` 解析。

## 第 84-87 行：导入冒烟测试（第 07 章）

```dockerfile
RUN python3 -B -c "import openpi, openpi_client; \
from openpi.training import config; from openpi.serving import websocket_policy_server; \
assert openpi.__file__.startswith('/workspace/src/'), openpi.__file__; \
print('brain imports OK', openpi.__file__)"
```

- import 服务启动必经的模块，不需要 GPU 和权重。
- `assert` 确认加载的 `openpi` 来自刚拷进来的代码。如果 `PYTHONPATH` 配错，或者 Python 从别处找到了同名包，构建就会失败。
- `-B` 保证发布的代码目录里不留 `__pycache__`。

## 第 89-90 行：启动命令（第 04 章）

```dockerfile
ENTRYPOINT ["/opt/nvidia/nvidia_entrypoint.sh"]
CMD ["python", "scripts/serve_policy_rtc.py", "--help"]
```

- `nvidia_entrypoint.sh` 来自 NGC PyTorch 基础镜像：打印版本横幅、检查环境，再 `exec "$@"` 执行 CMD。
- 默认 CMD 只打印帮助，避免误启动。实际参数在 docker-compose 的 `command:` 里指定。

## 第 95-118 行：vla-body 阶段

和 vla-brain 结构相同，只说不同之处：

```dockerfile
FROM ${REGISTRY}/vla-body-env:${ENV_TAG} AS vla-body
...
ENV ... PYTHONPATH=/opt/openpi-client/src:/workspace

WORKDIR /workspace
COPY --from=builder /export/body/ /workspace/
COPY --from=builder /export/brain/packages/openpi-client/ /opt/openpi-client/
COPY --from=builder /export/brain/LICENSE /opt/openpi-client/LICENSE
RUN mkdir -p /workspace/logs
```

- 基础镜像换成 `vla-body-env`，带 RealSense 和 Orbbec 相机 SDK。
- brain 的代码只拿 `openpi-client` 这一个包，body 用它通过 websocket 和 brain 通信。放在 `/opt/openpi-client`，和 body 自己的代码分开。
- 第三条 `COPY` 的源和目标都是单个文件，附带 openpi 的 Apache-2.0 LICENSE，因为分发了它的代码。
- `logs` 是日志的挂载点。
- 冒烟测试 import `vla_body` 的核心模块（`policy_client`、`cameras`、`shm_cameras`、`proto_utils`、`lowlevel`），并断言 `openpi_client` 来自 `/opt/openpi-client/`。
- 默认 `CMD ["bash"]`，实际运行命令由 docker-compose 指定。

## 怎么构建

不直接调用 `docker build`，用仓库里的脚本：

```bash
# 在 arm64 / Jetson Thor 上，仓库根目录执行
docker-deploy/vla/build.sh release --tag 2.1.0rc               # 构建 body 和 brain
docker-deploy/vla/build.sh release --tag 2.1.0rc --target body # 只构建 body
```

脚本实际执行的命令（以 body 为例）：

```bash
docker build \
    --file docker-deploy/vla/Dockerfile.release \
    --target vla-body \
    --build-arg ENV_TAG=1.1.0 \
    --build-arg GIT_COMMIT=<当前提交> \
    --build-arg RELEASE_VERSION=2.1.0rc \
    --tag robot-harbor.geekplus.com/gino/vla-body:2.1.0rc \
    <仓库根目录>
```

到这里，命令里的每个参数应该都能对上前面章节的内容了。

## 自测题

1. 删掉第 67 行的 `ARG GIT_COMMIT=unknown`，`ENV GIT_COMMIT` 会得到什么值？
2. `.dockerignore` 已经排除了 `**/__pycache__`，为什么第 48 行还要再删一次？
3. 如果在 docker-compose 里给 vla-brain 写了 `entrypoint: ["python"]` 但没写 `command`，容器启动后会发生什么？
4. 只修改 `brain/vla/openpi` 下某个 `*_test.py`，重新构建时哪些步骤会命中缓存？

<details>
<summary>参考答案</summary>

1. 空字符串。全局作用域里也没有 `GIT_COMMIT`，阶段内不声明 ARG，就读不到 `--build-arg` 传入的值。
2. 防御性写法。`Dockerfile.release.dockerignore` 是 BuildKit 的功能，用旧构建器时不生效，`__pycache__` 就会被拷进来。第 48 行保证无论用哪种构建器，结果都一样。
3. 覆盖 ENTRYPOINT 会清掉镜像的 CMD，容器只执行不带参数的 `python`。没有分配终端时，Python 读到空输入后立即退出；分配了终端则进入交互式解释器。
4. builder 阶段从 `COPY brain/vla/openpi` 开始全部重新执行。但测试文件在 builder 里被删掉了，`/export` 内容不变，所以两个发布阶段的 `COPY --from=builder` 及之后的步骤都命中缓存。

</details>
